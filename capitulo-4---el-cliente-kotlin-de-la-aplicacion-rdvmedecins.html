    5. Capítulo 4 - El cliente Kotlin de la aplicación RdvMedecins

    5.1. Descripción general de la arquitectura

    Este cliente se comunica con el servidor [rdvmedecins-nestjs-server] del curso, que permanece completamente sin cambios, mediante las mismas rutas HTTP (POST [/login], GET [/getAllDoctors], GET [/getAllClients], GET [/getDoctorScheduleOfDay/:doctorId/:day], POST [/addAppointment], POST [/deleteAppointment]), con el mismo envoltorio JSON [{ status, data }] y la misma autenticación por token [JWT] (encabezado [Authorization: Bearer <token>]).

    // =========================================================================
// RdvMedecinsApplication.kt
// -------------------------------------------------------------------------
// Primera mitad del lib/main.dart de la versión Flutter: construir,
// UNA SOLA VEZ, los servicios de la aplicación.
//
// ¿Por qué una clase Application? En Android, la pantalla (la Activity, ver
// MainActivity) se DESTRUYE y luego se RECREA en cada rotación del teléfono, en
// cada cambio del idioma del sistema, etc. Los servicios construidos en la
// Activity se reconstruirían, por lo tanto, en cada rotación. El
// objeto Application, en cambio, se crea cuando se inicia el proceso
// y vive tanto como este: es el lugar adecuado para los objetos que deben
// durar toda la vida de la aplicación. Se declara en
// AndroidManifest.xml (atributo android:name de la etiqueta <application>).
//
// El ORDEN de construcción importa, como en la versión Flutter:
// AuthService necesita SettingsService (la URL del servidor); el cliente
// HTTP autenticado necesita AuthService (el token); AppointmentService necesita
// el cliente HTTP autenticado y SettingsService.
// =========================================================================

package fr.rdvmedecins.client

import android.app.Application
import android.content.Context
import fr.rdvmedecins.client.core.http.AuthInterceptor
import fr.rdvmedecins.client.core.i18n.TranslationsService
import fr.rdvmedecins.client.core.services.AuthService
import fr.rdvmedecins.client.core.services.AppointmentService
import fr.rdvmedecins.client.core.services.SettingsService
import okhttp3.OkHttpClient
import java.util.concurrent.TimeUnit

class RdvMedecinsApplication : Application() {

    // lateinit: estas propiedades no nulas se inicializarán en
    // onCreate(), y no en el constructor (ver el curso de Kotlin)
    lateinit var settings: SettingsService
        private set
    lateinit var auth: AuthService
        private set
    lateinit var api: AppointmentService
        private set
    lateinit var translations: TranslationsService
        private set

    // llamado por Android cuando se inicia la aplicación, antes de cualquier pantalla
    override fun onCreate() {
        super.onCreate()

        // las preferencias de la aplicación: un pequeño archivo privado de clave/valor,
        // que sobrevive a la detención de la aplicación - el equivalente del
        // localStorage de un navegador
        val prefs = getSharedPreferences("rdvmedecins", Context.MODE_PRIVATE)

        // 1. Primero SettingsService: los demás lo necesitan
        settings = SettingsService(prefs)

        // 2. un cliente HTTP OkHttp "simple", usado por AuthService para
        //    POST /login. Timeouts cortos: en móvil, un mensaje de error rápido
        //    es mejor que una espera interminable si el servidor
        //    no es accesible (URL incorrecta, Wi-Fi apagado...).
        val plainHttp = OkHttpClient.Builder()
            .connectTimeout(10, TimeUnit.SECONDS)
            .readTimeout(15, TimeUnit.SECONDS)
            .build()
        auth = AuthService(settings, prefs, plainHttp)

        // 3. el cliente HTTP autenticado: una COPIA del anterior
        //    (newBuilder() reutiliza su configuración y sus conexiones),
        //    más el interceptor que agrega el token JWT
        val authHttp = plainHttp.newBuilder()
            .addInterceptor(AuthInterceptor(auth))
            .build()
        api = AppointmentService(authHttp, settings)

        // 4. las traducciones: sin dependencia de los demás servicios
        translations = TranslationsService(assets, prefs)
    }
}

    Comentemos este código:

    • línea 34: la clase extiende [android.app.Application]. Android crea una única instancia de ella cuando se inicia el proceso de la aplicación, antes que cualquier activity, y la conserva hasta que el proceso termina;
    • líneas 38–44: los cuatro servicios, declarados como [lateinit var ... private set]: no nulos, inicializados más tarde (en [onCreate]) y modificables solo por esta clase;

    • líneas 63–66: un cliente [OkHttp] “simple”, con tiempos de espera cortos. Un cliente OkHttp está pensado para COMPARTIRSE: gestiona su propio grupo de conexiones reutilizables;
    • línea 67: [AuthService] recibe el cliente simple: la ruta [/login] es la única ruta pública del servidor; no requiere un token;

// AppViewModel.kt
// -------------------------------------------------------------------------
// El ESTADO y la LÓGICA de la pantalla principal: la parte "_AppRootState" del
// lib/app.dart de la versión Flutter (médicos, pacientes, agenda
// mostrada, error, última búsqueda...) y las reacciones a las
// acciones del usuario (buscar una agenda, reservar, cancelar).

// AppRoot (ver App.kt)? Porque la Activity se destruye y se
// recrea en cada rotación de pantalla (ver RdvMedecinsApplication): un
// estado local se perdería - la agenda mostrada desaparecería con la más mínima
// inclinación del teléfono. Un ViewModel (biblioteca "lifecycle" de Android Jetpack)
// SOBREVIVE a esas recreaciones: Android lo conserva y
// se lo entrega a la nueva Activity. Solo se destruye cuando se abandona
// la pantalla definitivamente. Flutter no tiene este problema: allí la rotación
// no destruye nada, solo cambia el tamaño de la pantalla.
//
// La separación resultante es clásica en Android: App.kt MUESTRA, este
// ViewModel DECIDE y llama a los servicios.

package fr.rdvmedecins.client

import android.util.Log
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.setValue

import androidx.lifecycle.ViewModel

import fr.rdvmedecins.client.core.models.DoctorDaySchedule
import fr.rdvmedecins.client.core.models.Client

import kotlinx.coroutines.CancellationException
import kotlinx.coroutines.launch

class AppViewModel(
    private val auth: AuthService,
    private val api: AppointmentService,
) : ViewModel() {

    // — estado mostrado por App.kt (lectura pública, escritura privada) —
    var doctors by mutableStateOf<List<Doctor>>(emptyList())
        private set
    var clients by mutableStateOf<List<Client>>(emptyList())
        private set
    var schedule by mutableStateOf<DoctorDaySchedule?>(null)
        private set
    var error by mutableStateOf<String?>(null)
        private set

    // la franja que se está reservando: no nula = el diálogo de reserva
    // está abierto (ver App.kt y BookingDialog.kt)
    var slotBeingBooked by mutableStateOf<SlotJson?>(null)
        private set

    // la última búsqueda (médico + día), para actualizar la agenda después de
    // una reserva o una cancelación. Nunca se muestra: bastan
    // propiedades simples, no hace falta convertirlas en estados de Compose.
    private var lastDoctorId: Int? = null
    private var lastDay: String? = null

    init {
        // snapshotFlow { ... } convierte la lectura de un estado de Compose en un
        // FLOW de valores: emite de inmediato el valor actual de auth.isLoggedIn,
        // luego cada nuevo valor. Es el equivalente exacto del
        // "watch(() => auth.isLoggedIn, ..., { immediate: true })" de Vue.js
        // - y de la suscripción addListener(...) + llamada inicial
        // que la versión Flutter debía escribir a mano.
        // viewModelScope: las corrutinas lanzadas en este ámbito se cancelan
        // automáticamente cuando se destruye el ViewModel (ya no hace falta
        // el removeListener(...) del dispose() del lado de Flutter).
        viewModelScope.launch {
            snapshotFlow { auth.isLoggedIn }.collect { loggedIn ->
                if (loggedIn) {
                    loadInitialLists()
                } else {
                    reset()
                }
            }
        }
    }

    // -----------------------------------------------------------------------
    // al iniciar sesión (o cuando se restaura una sesión recordada):
    // cargamos los médicos y los pacientes una sola vez. Dos
    // corrutinas separadas: las dos solicitudes se envían EN PARALELO.
    // -----------------------------------------------------------------------
    private fun loadInitialLists() {
        runSafely { doctors = api.getAllDoctors() }
        runSafely { clients = api.getAllClients() }
    }

    // -----------------------------------------------------------------------
    // al cerrar sesión (botón, o token rechazado por el servidor):
    // purgamos el estado de negocio, para que un nuevo usuario no vea, ni siquiera por
    // un instante, la agenda del usuario anterior
    // -----------------------------------------------------------------------
    private fun reset() {
        doctors = emptyList()
        clients = emptyList()
        schedule = null
        error = null
        slotBeingBooked = null
        lastDoctorId = null
        lastDay = null
    }

    // botón "Log out": basta con cerrar la sesión en AuthService -
    // snapshotFlow (ver init) activa entonces reset()
    fun logOut() {
        auth.logOut()
    }

    // -----------------------------------------------------------------------
    // botón "View schedule" de DoctorDayPicker
    // -----------------------------------------------------------------------
    fun searchSchedule(doctorId: Int, day: String) {
        error = null
        lastDoctorId = doctorId
        lastDay = day
        loadSchedule()
    }

    // -----------------------------------------------------------------------
    // botón "Book" de ScheduleView: nos limitamos a ABRIR el
    // diálogo, recordando la franja correspondiente. Con Compose, un diálogo
    // forma parte de la visualización como todo lo demás: se
    // muestra mientras slotBeingBooked no sea nulo (ver App.kt) -
    // el mismo principio que la prop "open" del BookingDialog.vue de la
    // variante Vue.js, lo contrario del showDialog(...) de Flutter.
    // -----------------------------------------------------------------------
    fun requestBooking(slot: SlotJson) {
        slotBeingBooked = slot
    }

    // botón "Cancel" del diálogo (o toque fuera de él)
    fun closeBooking() {
        slotBeingBooked = null
    }

    // botón "Confirm" del diálogo
    fun confirmBooking(clientId: Int) {
        val slot = slotBeingBooked ?: return
        val day = lastDay ?: return
        slotBeingBooked = null // cierra el diálogo
        runSafely {
            api.addAppointment(day, clientId, slot.id)
            loadSchedule() // la franja ahora aparece ocupada
        }
    }

    // -----------------------------------------------------------------------
    // botón "Cancel" de una franja ocupada, en ScheduleView
    // -----------------------------------------------------------------------
    fun cancelAppointment(appointment: AppointmentJson) {
        runSafely {
            api.deleteAppointment(appointment.id)
            loadSchedule() // la franja vuelve a quedar libre
        }
    }

    private fun loadSchedule() {
        val doctorId = lastDoctorId ?: return
        val day = lastDay ?: return
        runSafely { schedule = api.getDoctorScheduleOfDay(doctorId, day) }
    }

    // -----------------------------------------------------------------------
    // ejecuta [action] en una corrutina del ViewModel y convierte cualquier
    // excepción en un mensaje de error mostrado en pantalla. Factorizar este
    // try/catch evita repetirlo en cada método anterior.
    // Una CancellationException NO es un error: es la señal de cancelación
    // de una corrutina (ViewModel destruido), que debe dejarse
    // propagar.
    // -----------------------------------------------------------------------
    private fun runSafely(action: suspend () -> Unit) {
        viewModelScope.launch {
            try {
                action()
            } catch (e: CancellationException) {
                throw e
            } catch (e: Exception) {
                Log.w("RdvMedecins", "a server call failed", e) // ver Logcat
                error = e.message ?: e.toString()
            }
        }
    }
}

    • líneas 65–66: la búsqueda más reciente (médico y día), usada para actualizar el calendario después de una reserva o una cancelación. Son simples propiedades privadas: nunca se muestran;

// (List<String>) mientras que, en caso de éxito, esperamos por ejemplo una agenda.

package fr.rdvmedecins.client.core.models

import kotlinx.serialization.DeserializationStrategy
import kotlinx.serialization.json.Json
import kotlinx.serialization.json.JsonNull
import kotlinx.serialization.json.int
import kotlinx.serialization.json.jsonObject
import kotlinx.serialization.json.jsonPrimitive

// la configuración JSON compartida por todo el cliente:
// - ignoreUnknownKeys: el servidor envía campos que este cliente
//   no usa (p. ej. la "version" de un médico) - los ignoramos en lugar de
//   lanzar una excepción;
// - explicitNulls = false: al codificar, una propiedad nula no se
//   escribe (sin efecto en las clases de este cliente, pero más cercano al
//   comportamiento de JSON.stringify del lado de JavaScript).
val ApiJson = Json {
    ignoreUnknownKeys = true
    explicitNulls = false
}

// excepción lanzada cuando el servidor responde con un status de negocio
// distinto de 0 (recurso no encontrado, fecha inválida, error del servidor)
class ResponseException(val status: Int) :
    Exception("The server responded with error status $status")

// decodifica el cuerpo de una respuesta {status, data} y devuelve "data" en el
// tipo T descrito por [deserializer] (p. ej. Doctor.serializer(), o
// ListSerializer(Doctor.serializer()) para una lista de médicos)
fun <T> decodeResponse(body: String, deserializer: DeserializationStrategy<T>): T {
    // 1. el envoltorio, como árbol JSON genérico
    val envelope = ApiJson.parseToJsonElement(body).jsonObject
    // 2. el status de negocio
    val status = envelope.getValue("status").jsonPrimitive.int
    if (status != 0) {
        throw ResponseException(status)
    }
    // 3. "data", decodificado solo ahora, al tipo esperado
    val data = envelope["data"] ?: JsonNull
    return ApiJson.decodeFromJsonElement(deserializer, data)
}

    Comentemos este código:

    • líneas 36–38: [ApiJson]—la configuración JSON compartida por todo el cliente. [ignoreUnknownKeys = true]: el servidor envía campos que el cliente no usa (p. ej., [version] de un médico); sin este ajuste, kotlinx.serialization lanzaría una excepción al encontrar la primera clave desconocida;
    • línea 43: [ResponseException]—la excepción que se lanza cuando el servidor responde con un estado de negocio distinto de 0;
    • Línea 49: [decodeResponse(body, deserializer)] - una función genérica: el parámetro [deserializer] (por ejemplo, [Doctor.serializer()], generado por el plugin) especifica el tipo [T] en el que se decodifica [data];
    • Líneas 51–59: la decodificación se realiza en DOS pasos. Primero, el contenedor se lee como un árbol JSON genérico ([JsonObject]); luego, solo si [status] es 0, se decodifica [data] en el tipo esperado. Motivo: en caso de error, el servidor coloca una lista de mensajes en [data], mientras que en caso de éxito se esperaría, por ejemplo, un calendario. Decodificar de inmediato todo el contenedor en el tipo de éxito fallaría ante una respuesta de error, antes de poder leer el estado.

    // de forma SÍNCRONA: getString(...) responde de inmediato (las preferencias se
    // cargan en memoria en el primer acceso). "private set": solo esta
    // clase puede modificar la URL, mediante changeUrl(...).
    var apiBaseUrl: String by mutableStateOf(prefs.getString(URL_KEY, null) ?: DEFAULT_URL)
        private set

    fun changeUrl(url: String) {
        if (url == apiBaseUrl) {
            return // evita una nueva visualización y una escritura innecesarias
        }
        apiBaseUrl = url
        // edit { ... }: función de extensión de androidx.core (core-ktx);
        // abre un editor, ejecuta el bloque y luego llama a apply(), que
        // escribe en disco en segundo plano, sin bloquear la UI.
        prefs.edit { putString(URL_KEY, url) }
    }

    companion object {
        // 10.0.2.2: en el emulador de Android, esta dirección especial
        // designa la máquina anfitriona, aquella donde se ejecuta el servidor NestJS
        // (localhost designaría al propio emulador, ver capítulo 5)

        private const val URL_KEY = "rdvmedecins.apiBaseUrl"
    }
}

package fr.rdvmedecins.client.core.services

import android.content.SharedPreferences
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.setValue
import androidx.core.content.edit
import fr.rdvmedecins.client.core.models.ApiJson
import fr.rdvmedecins.client.core.models.LoginRequest
import fr.rdvmedecins.client.core.models.LoginResult
import fr.rdvmedecins.client.core.models.Role
import fr.rdvmedecins.client.core.models.decodeResponse
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext
import okhttp3.MediaType.Companion.toMediaType
import okhttp3.OkHttpClient
import okhttp3.Request
import okhttp3.RequestBody.Companion.toRequestBody
import java.io.IOException

class AuthService(
    private val settings: SettingsService,
    private val prefs: SharedPreferences,
    // un cliente HTTP SIN el interceptor de autenticación: POST /login
    // es la única ruta pública del servidor, no hay ningún token que
    // enviar (ver RdvMedecinsApplication)
    private val http: OkHttpClient,
) {
    // estado de la sesión, observado por la UI
    var isLoggedIn by mutableStateOf(false)
        private set
    var login by mutableStateOf<String?>(null)
        private set
    var name by mutableStateOf<String?>(null)
        private set
    var role by mutableStateOf<Role?>(null)
        private set

    // el token nunca se MUESTRA: no hace falta convertirlo en un estado de Compose.
    // Sin embargo, AuthInterceptor lo lee en un hilo de red:
    // @Volatile garantiza que ese hilo siempre vea el último valor
    // escrito por el hilo principal.
    @Volatile
    var accessToken: String? = null
        private set

    // propiedad calculada: vuelve a leer role en cada acceso (y, cuando se lee durante una
    // visualización, suscribe la visualización a los cambios de role)
    val isAdmin: Boolean
        get() = role == Role.ADMIN

    init {
        restoreSession()
    }

    // -----------------------------------------------------------------------
    // vuelve a leer una sesión posiblemente guardada durante un inicio anterior
    // -----------------------------------------------------------------------
    private fun restoreSession() {
        val raw = prefs.getString(SESSION_KEY, null) ?: return // ninguna sesión guardada
        try {
            // la sesión se guardó como un LoginResult
            // serializado en JSON (ver logIn): lo volvemos a leer tal cual
            applySession(ApiJson.decodeFromString(LoginResult.serializer(), raw))
        } catch (e: Exception) {
            // contenido ilegible (p. ej. el formato de una versión antigua de
            // la aplicación): lo olvidamos, el usuario volverá a iniciar sesión
            prefs.edit { remove(SESSION_KEY) }
        }
    }

    // -----------------------------------------------------------------------
    // POST /login. "suspend": esta función puede pausarse durante el
    // tiempo que el servidor tarda en responder, SIN bloquear el hilo que la llama -
    // el equivalente de una función async que devuelve un Future<LoginResult>
    // del lado de Dart. Lanza una excepción si el inicio de sesión falla.
    // -----------------------------------------------------------------------
    suspend fun logIn(login: String, password: String): LoginResult {
        // withContext(Dispatchers.IO): el bloque se ejecuta en un hilo
        // reservado para entrada/salida. Android PROHÍBE cualquier acceso a la red
        // desde el hilo principal (NetworkOnMainThreadException): es
        // el que dibuja la UI, nunca debe esperar.
        val result = withContext(Dispatchers.IO) {
            val body = ApiJson.encodeToString(LoginRequest.serializer(), LoginRequest(login, password))
            val request = Request.Builder()
                .url("${settings.apiBaseUrl}/login")
                .post(body.toRequestBody(JSON_TYPE))
                .build()
            // execute(): una llamada BLOQUEANTE - inofensiva aquí, estamos en un hilo de
            // entrada/salida. use { } cierra la respuesta al final del
            // bloque, pase lo que pase (el equivalente del
            // try-with-resources de Java, ver el curso de Kotlin).
            http.newCall(request).execute().use { response ->
                // credenciales incorrectas: el servidor responde 401 Unauthorized
                if (!response.isSuccessful) {
                    throw IOException("Login failed (HTTP ${response.code})")
                }
                decodeResponse(response.body!!.string(), LoginResult.serializer())
            }
        }
        // de vuelta en el hilo del llamador (el hilo principal):
        // es aquí, y no en el hilo de entrada/salida, donde modificamos el
        // estado observado por la UI
        applySession(result)
        prefs.edit { putString(SESSION_KEY, ApiJson.encodeToString(LoginResult.serializer(), result)) }
        return result
    }

    // -----------------------------------------------------------------------
    // cierre de sesión: olvidamos la sesión, en memoria y en las preferencias.
    // Debe llamarse en el hilo principal (ver AuthInterceptor).
    // -----------------------------------------------------------------------
    fun logOut() {
        accessToken = null
        login = null
        name = null
        role = null
        isLoggedIn = false
        prefs.edit { remove(SESSION_KEY) }
    }

    private fun applySession(session: LoginResult) {
        accessToken = session.accessToken
        login = session.login
        name = session.name
        role = session.role
        isLoggedIn = true
    }

    companion object {
        private const val SESSION_KEY = "rdvmedecins.session"
        private val JSON_TYPE = "application/json; charset=utf-8".toMediaType()
    }
}

    Comentemos este código:

    • líneas 51–57: el estado de la sesión, tal como lo observa la interfaz: [isLoggedIn], [login], [name], [role];
    • líneas 64–65: [accessToken] nunca se muestra: no hace falta convertirlo en un estado de Compose. Sin embargo, [AuthInterceptor] lo lee en un hilo de red: [@Volatile] garantiza que este hilo siempre vea el último valor escrito por el hilo principal;
    • líneas 70–71: [isAdmin]—una propiedad calculada ([get() = ...]), que se vuelve a leer en cada acceso;
    • líneas 73–85: el bloque [init] restaura la sesión almacenada, si existe, en cuanto se inicializa el servicio: las preferencias se leen de forma sincrónica. La sesión se almacena como un [LoginResult] serializado en JSON, que luego se vuelve a leer mediante [decodeFromString(LoginResult.serializer(), raw)];
    • línea 99: [suspend fun logIn(...)]—una función suspendida: se pausa mientras espera la respuesta del servidor, sin bloquear el hilo que la llama;
    • línea 104: [withContext(Dispatchers.IO) { ... }]—la solicitud se ejecuta en un hilo de E/S; el valor de la última expresión del bloque (el [LoginResult] decodificado) es el resultado;
    • líneas 106–109: la solicitud de OkHttp: [Request.Builder()], la URL y luego [.post(body.toRequestBody(JSON_TYPE))]—el cuerpo JSON, con su tipo MIME;
    • Línea 114: [execute()] ejecuta la solicitud de forma BLOQUEANTE, sin riesgo en un hilo de E/S. [use { response -> ... }] cierra la respuesta al final del bloque, pase lo que pase: el equivalente de `try-with-resources` de Java;
    • Líneas 116–117: credenciales incorrectas: el servidor devuelve una respuesta 401 Unauthorized; se lanza una excepción, que [LoginPage] convierte en un mensaje de error;

package fr.rdvmedecins.client.core.services

import fr.rdvmedecins.client.core.models.DoctorDaySchedule
import fr.rdvmedecins.client.core.models.AddAppointmentRequest
import fr.rdvmedecins.client.core.models.Client
import fr.rdvmedecins.client.core.models.ApiJson
import fr.rdvmedecins.client.core.models.Doctor
import fr.rdvmedecins.client.core.models.AppointmentJson
import fr.rdvmedecins.client.core.models.DeleteAppointmentRequest
import fr.rdvmedecins.client.core.models.decodeResponse
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext
import kotlinx.serialization.DeserializationStrategy
import kotlinx.serialization.builtins.ListSerializer
import kotlinx.serialization.json.JsonElement
import okhttp3.MediaType.Companion.toMediaType
import okhttp3.OkHttpClient
import okhttp3.Request
import okhttp3.RequestBody.Companion.toRequestBody
import java.io.IOException

class AppointmentService(
    private val http: OkHttpClient,
    private val settings: SettingsService,
) {
    // -----------------------------------------------------------------------
    // las rutas GET
    // -----------------------------------------------------------------------
    suspend fun getAllDoctors(): List<Doctor> =
        call(getRequest("/getAllDoctors"), ListSerializer(Doctor.serializer()))

    suspend fun getAllClients(): List<Client> =
        call(getRequest("/getAllClients"), ListSerializer(Client.serializer()))

    suspend fun getDoctorScheduleOfDay(doctorId: Int, day: String): DoctorDaySchedule =
        call(getRequest("/getDoctorScheduleOfDay/$doctorId/$day"), DoctorDaySchedule.serializer())

    // -----------------------------------------------------------------------
    // las rutas POST (reservadas por el servidor para el rol ADMIN)
    // -----------------------------------------------------------------------
    suspend fun addAppointment(day: String, clientId: Int, slotId: Int): AppointmentJson {
        val body = ApiJson.encodeToString(
            AddAppointmentRequest.serializer(),
            AddAppointmentRequest(day, clientId, slotId),
        )
        return call(postRequest("/addAppointment", body), AppointmentJson.serializer())
    }

    suspend fun deleteAppointment(appointmentId: Int) {
        val body = ApiJson.encodeToString(DeleteAppointmentRequest.serializer(), DeleteAppointmentRequest(appointmentId))
        // "data" es null en caso de éxito: lo decodificamos como un elemento
        // JSON cualquiera, y lo ignoramos
        call(postRequest("/deleteAppointment", body), JsonElement.serializer())
    }

    // -----------------------------------------------------------------------
    // construcción de las solicitudes
    // -----------------------------------------------------------------------
    private fun getRequest(path: String): Request =
        Request.Builder().url(settings.apiBaseUrl + path).get().build()

    private fun postRequest(path: String, jsonBody: String): Request =
        Request.Builder()
            .url(settings.apiBaseUrl + path)
            .post(jsonBody.toRequestBody(JSON_TYPE))
            .build()

    // -----------------------------------------------------------------------
    // ejecuta una solicitud en un hilo de entrada/salida y decodifica la
    // respuesta {status, data}. El parámetro genérico <T> y el
    // [deserializer] que lo acompaña indican a qué tipo decodificar
    // "data" - el papel del parámetro parseData de la versión Flutter.
    // -----------------------------------------------------------------------
    private suspend fun <T> call(request: Request, deserializer: DeserializationStrategy<T>): T =
        withContext(Dispatchers.IO) {
            http.newCall(request).execute().use { response ->
                // 401 (token rechazado), 403 (rol insuficiente), 404...: el
                // cuerpo no es un envoltorio {status, data}
                if (!response.isSuccessful) {
                    throw IOException("HTTP error ${response.code}")
                }
                decodeResponse(response.body!!.string(), deserializer)
            }
        }

    companion object {
        private val JSON_TYPE = "application/json; charset=utf-8".toMediaType()
    }
}

// AuthInterceptor.kt
// -------------------------------------------------------------------------
// Adaptación de lib/core/http/auth_http_client.dart. Dos responsabilidades,
// las mismas que en todas las variantes de este curso:
//   1. agregar el encabezado "Authorization: Bearer <token>" a cada solicitud;
//   2. cerrar la sesión del usuario si el servidor responde 401 Unauthorized
//      (token expirado o inválido).
//
// La versión Flutter envolvía el cliente HTTP en una clase propia,
// por falta de un mecanismo de interceptación en el paquete http. OkHttp, en cambio,
// ofrece INTERCEPTORES: objetos por los que pasa cada
// solicitud antes de enviarse, y cada respuesta antes de volver al
// llamador - exactamente la noción de interceptor HTTP de Angular
// (auth.interceptor.ts en la variante Angular de este curso).

package fr.rdvmedecins.client.core.http

import android.os.Handler
import android.os.Looper
import fr.rdvmedecins.client.core.services.AuthService
import okhttp3.Interceptor
import okhttp3.Response

class AuthInterceptor(private val auth: AuthService) : Interceptor {

    // un Handler vinculado al hilo principal: nos permite entregarle
    // trabajo desde otro hilo (ver intercept más abajo)
    private val mainThread = Handler(Looper.getMainLooper())

    // llamado por OkHttp para CADA solicitud, en un hilo de red
    override fun intercept(chain: Interceptor.Chain): Response {
        // 1. la solicitud original, más el token si lo hay. Una
        //    solicitud de OkHttp es inmutable: newBuilder() hace una copia
        //    modificable de ella.
        val token = auth.accessToken
        val request = if (token == null) {
            chain.request()
        } else {
            chain.request().newBuilder()
                .header("Authorization", "Bearer $token")
                .build()
        }
        // 2. dejamos que la solicitud continúe su camino hacia el servidor
        val response = chain.proceed(request)
        // 3. token rechazado: cerramos la sesión del usuario. Este método
        //    se ejecuta en un hilo de red; sin embargo, logOut() modifica el
        //    estado mostrado por la UI: por eso entregamos esta llamada al
        //    hilo principal (post), sin esperar a que se ejecute - el
        //    equivalente del unawaited(auth.logOut()) de la versión Flutter.
        if (response.code == 401) {
            mainThread.post { auth.logOut() }
        }
        return response
    }
}

    Comentemos este código:

    • Línea 26: la clase implementa la interfaz [okhttp3.Interceptor]. OkHttp hace pasar cada solicitud por los interceptores del cliente antes de enviarla, y cada respuesta antes de devolverla a quien llama: es el concepto de los interceptores HTTP de Angular. La versión Flutter, al carecer de un mecanismo así en el paquete [http], envolvía el cliente HTTP en su propia clase;
    • línea 30: un [Handler] asociado con el hilo principal ([Looper.getMainLooper()]): permite delegarle trabajo desde otro hilo;
    • líneas 41–43: una solicitud de OkHttp es INMUTABLE; [newBuilder()] crea una copia modificable de ella, complementada con el encabezado [Authorization];
    • línea 46: [chain.proceed(request)]—la solicitud continúa hacia el servidor; el método devuelve la respuesta;
    • líneas 52–53: token rechazado (401): [intercept] se ejecuta en un hilo de red, pero [logOut()] modifica el estado mostrado. Por lo tanto, la llamada se delega al hilo principal ([post { ... }]), sin esperar a que se ejecute: el equivalente de [unawaited(auth.logOut())] en la versión Flutter.

// en app/src/main/assets/i18n/: la carpeta assets/ de un proyecto Android
// se incrusta tal cual en la aplicación (el archivo .apk), como los

// aplicación se basa en archivos de recursos res/values/strings.xml
// (inglés) y res/values-fr/strings.xml (francés), y el sistema
// elige el archivo correcto según el idioma del TELÉFONO. Este documento
// conserva los diccionarios JSON compartidos por todas las variantes del curso,
// y el cambio FR/EN dentro de la propia aplicación, como lo hacía la

package fr.rdvmedecins.client.core.i18n

import android.content.SharedPreferences
import android.content.res.AssetManager
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.setValue
import androidx.core.content.edit
import fr.rdvmedecins.client.core.models.ApiJson
import kotlinx.serialization.json.JsonElement
import kotlinx.serialization.json.JsonObject
import kotlinx.serialization.json.JsonPrimitive
import kotlinx.serialization.json.jsonObject

class TranslationsService(
    private val assets: AssetManager,
    private val prefs: SharedPreferences,
) {
    // el idioma mostrado: un estado de Compose. Como t(...) más abajo LEE
    // esta propiedad, todo texto mostrado con t(...) se vuelve a mostrar
    // automáticamente cuando cambia el idioma - sin context.watch<...>() que
    // escribir, a diferencia de la versión Flutter.
    var currentLanguage by mutableStateOf(prefs.getString(LANGUAGE_KEY, null) ?: DEFAULT_LANGUAGE)
        private set

    // los diccionarios ya cargados, por idioma ("fr" -> {...})
    private val dictionaries = mutableMapOf<String, JsonObject>()

    fun changeLanguage(language: String) {
        if (language == currentLanguage) {
            return
        }
        dictionary(language) // carga el diccionario ANTES de cambiar el idioma
        currentLanguage = language
        prefs.edit { putString(LANGUAGE_KEY, language) }
    }

    // -----------------------------------------------------------------------
    // t("LOGIN.TITLE"): recorre el diccionario del idioma actual
    // segmento por segmento ("LOGIN", luego "TITLE"). Si no se encuentra la clave,
    // se devuelve la propia clave: el texto faltante permanece así
    // visible en pantalla, sin hacer que la aplicación falle.
    // -----------------------------------------------------------------------
    fun t(key: String): String {
        var currentValue: JsonElement = dictionary(currentLanguage)
        for (segment in key.split('.')) {
            currentValue = (currentValue as? JsonObject)?.get(segment) ?: return key
        }
        val primitive = currentValue as? JsonPrimitive
        return if (primitive != null && primitive.isString) primitive.content else key
    }

    // -----------------------------------------------------------------------
    // el diccionario de un idioma, cargado la primera vez que se necesita y luego conservado en
    // memoria. getOrPut: devuelve el valor asociado a la clave, o ejecuta
    // el bloque, almacena su resultado y lo devuelve. La lectura es
    // síncrona: los dos archivos pesan apenas unos cientos de
    // bytes, leerlos es instantáneo.
    // -----------------------------------------------------------------------
    private fun dictionary(language: String): JsonObject =
        dictionaries.getOrPut(language) {
            assets.open("i18n/$language.json").bufferedReader().use { reader ->
                ApiJson.parseToJsonElement(reader.readText()).jsonObject
            }
        }

    companion object {
        private const val LANGUAGE_KEY = "rdvmedecins.language"
        private val DEFAULT_LANGUAGE = if (java.util.Locale.getDefault().language == "fr") "fr" else "en"
    }
}

    Comentemos este código:

    • Líneas 43–44: [currentLanguage]—un estado observable. Como [t(...)] LEE esta propiedad, cualquier función @Composable que muestre texto con [t(...)] se recompone automáticamente cuando cambia el idioma: no hace falta escribir ningún [context.watch<...>()];
    • líneas 49–55: [changeLanguage(...)]—carga el diccionario ANTES de cambiar de idioma, y luego guarda la selección en las preferencias;
    • Líneas 64–70: [t("LOGIN.TITLE")]—recorre el diccionario segmento por segmento. [as?] es la conversión de tipo “segura” de Kotlin: devuelve [null] (en lugar de lanzar una excepción) si el objeto no es del tipo solicitado; combinada con [?: return key], hace que se devuelva la propia clave en cuanto no se encuentra un segmento: el texto faltante permanece visible en la pantalla;
    • líneas 80–83: [dictionary(language)] – [getOrPut] devuelve el diccionario ya cargado, o ejecuta el bloque (que lee [assets/i18n/<language>.json]), almacena su resultado y lo devuelve. La lectura es sincrónica: ambos archivos pesan apenas unos cientos de bytes.

import androidx.compose.foundation.layout.fillMaxWidth

// las API ExposedDropdownMenu* todavía están marcadas como "experimentales" por
// Material 3: @OptIn indica que las usamos a sabiendas
@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun <T> DropdownList(
    label: String,
    placeholder: String,     // texto mostrado mientras no se haya elegido nada
    items: List<T>,
    selectedId: Int?,        // id del elemento elegido, o null
    idOf: (T) -> Int,
    itemLabel: (T) -> String,
    onSelect: (Int) -> Unit,
    modifier: Modifier = Modifier,
) {
    // menú abierto o cerrado: un estado LOCAL a esta función, recordado de una
    // visualización a la siguiente por remember (ver capítulo 3)
    var menuOpen by remember { mutableStateOf(false) }
    val selected = items.firstOrNull { idOf(it) == selectedId }

    ExposedDropdownMenuBox(
        expanded = menuOpen,
        onExpandedChange = { menuOpen = it },
        modifier = modifier,
    ) {
        // el campo que muestra la elección actual; menuAnchor(...) lo convierte en
        // el punto de anclaje del menú (un clic en él abre el menú)
        OutlinedTextField(
            value = selected?.let(itemLabel) ?: "",
            onValueChange = {},
            readOnly = true,
            singleLine = true,
            label = { Text(label) },
            placeholder = { Text(placeholder) },
            trailingIcon = { ExposedDropdownMenuDefaults.TrailingIcon(expanded = menuOpen) },
            modifier = Modifier
                .menuAnchor(ExposedDropdownMenuAnchorType.PrimaryNotEditable)
                .fillMaxWidth(),
        )
        // el menú propiamente dicho: un DropdownMenuItem por elemento
        ExposedDropdownMenu(expanded = menuOpen, onDismissRequest = { menuOpen = false }) {
            items.forEach { item ->
                DropdownMenuItem(
                    text = { Text(itemLabel(item)) },
                    onClick = {
                        onSelect(idOf(item))
                        menuOpen = false
                    },
                )
            }
        }
    }
}

    Analicemos este código:

    • líneas 38–46: [fun <T> DropdownList(...)]—una función @Composable GENÉRICA: muestra tanto médicos como pacientes. [idOf] especifica cómo identificar un elemento, [itemLabel] cómo mostrarlo y [onSelect] indica el identificador elegido;
    • línea 46: [modifier: Modifier = Modifier]—la convención de Compose: todo componente reutilizable acepta un modifier, que se aplica a su elemento raíz, para que quien lo llama pueda ajustar su tamaño o sus márgenes;
    • línea 50: [var menuOpen by remember { mutableStateOf(false) }]—el estado local del componente: menú abierto o cerrado;
    • línea 53: [ExposedDropdownMenuBox]—el contenedor, que administra la apertura y el cierre del menú;
    • líneas 60–69: el campo de solo lectura que muestra la selección actual. [menuAnchor(...)] sirve como punto de anclaje del menú: al tocarlo, se abre el menú;
    • líneas 73–79: el menú en sí: un [DropdownMenuItem] por elemento, generado mediante un bucle [forEach].

@Composable
fun LoginPage() {
    val auth = LocalAuth.current
    val t = LocalTranslations.current::t

    // estado local de la pantalla
    // rememberSaveable: el valor se recuerda de una visualización a la siguiente
    // Y sobrevive a la recreación de la Activity (rotación de pantalla) - un
    // login a medio escribir no se pierde si se gira el teléfono.
    var login by rememberSaveable { mutableStateOf("") }
    var password by rememberSaveable { mutableStateOf("") }
    // la clave de traducción del mensaje de error (y no el mensaje traducido:
    // así sigue un cambio de idioma), o null
    var error by rememberSaveable { mutableStateOf<String?>(null) }
    // solo remember: un inicio de sesión en curso no necesita sobrevivir a una rotación
    var inProgress by remember { mutableStateOf(false) }

    // un ámbito de corrutinas vinculado a esta pantalla: las corrutinas
    // lanzadas en él se cancelan si la pantalla desaparece
    val scope = rememberCoroutineScope()

    // una función local (ver el curso de Kotlin): la validación del
    // formulario, llamada por el botón Y por la tecla "Done" del teclado
    fun submit() {
        if (login.isBlank() || password.isEmpty() || inProgress) {
            return
        }
        error = null
        inProgress = true
        scope.launch {
            try {
                // en caso de éxito, AuthService pone isLoggedIn en true:
                // App.kt reemplaza entonces AUTOMÁTICAMENTE esta pantalla por
                // la agenda - aquí no hay nada más que hacer
                auth.logIn(login.trim(), password)
            } catch (e: CancellationException) {
                throw e
            } catch (e: Exception) {
                // la causa exacta (servidor inaccesible, credenciales incorrectas...)
                // se escribe en el registro de Android (pestaña Logcat de Android
                // Studio); el usuario ve un mensaje simple
                Log.w("RdvMedecins", "login failed", e)
                error = "LOGIN.ERROR"
            } finally {
                inProgress = false
            }
        }
    }

    // Box + Alignment.TopCenter: la tarjeta se centra horizontalmente
    Box(modifier = Modifier.fillMaxWidth(), contentAlignment = Alignment.TopCenter) {
        Card(modifier = Modifier.widthIn(max = 420.dp).fillMaxWidth()) {
            Column(
                modifier = Modifier.padding(24.dp),
                verticalArrangement = Arrangement.spacedBy(12.dp),
            ) {
                Text(t("LOGIN.TITLE"), style = MaterialTheme.typography.titleLarge)

                error?.let { key ->
                    Surface(
                        color = MaterialTheme.colorScheme.errorContainer,
                        contentColor = MaterialTheme.colorScheme.onErrorContainer,
                        shape = RoundedCornerShape(4.dp),
                        modifier = Modifier.fillMaxWidth(),
                    ) {
                        Text(t(key), modifier = Modifier.padding(8.dp))
                    }
                }

                OutlinedTextField(
                    value = login,
                    onValueChange = { login = it },
                    label = { Text(t("LOGIN.LOGIN_LABEL")) },
                    singleLine = true,
                    // tecla "Next" del teclado: pasa al campo siguiente
                    keyboardOptions = KeyboardOptions(imeAction = ImeAction.Next),
                    modifier = Modifier.fillMaxWidth(),
                )

                OutlinedTextField(
                    value = password,
                    onValueChange = { password = it },
                    label = { Text(t("LOGIN.PASSWORD_LABEL")) },
                    singleLine = true,
                    // muestra puntos en lugar de los caracteres
                    visualTransformation = PasswordVisualTransformation(),
                    keyboardOptions = KeyboardOptions(
                        keyboardType = KeyboardType.Password,
                        imeAction = ImeAction.Done,
                    ),
                    // tecla "Done" del teclado: envía el formulario
                    keyboardActions = KeyboardActions(onDone = { submit() }),
                    modifier = Modifier.fillMaxWidth(),
                )

                Spacer(Modifier.height(4.dp))
                Button(
                    onClick = { submit() },
                    enabled = !inProgress,
                    modifier = Modifier.fillMaxWidth(),
                ) {
                    Text(if (inProgress) t("LOGIN.SUBMITTING") else t("LOGIN.SUBMIT"))
                }

                Text(
                    text = "${t("LOGIN.DEMO_ACCOUNTS_PREFIX")} admin / admin ${t("LOGIN.DEMO_ACCOUNTS_ADMIN")} " +
                        "${t("LOGIN.DEMO_ACCOUNTS_OR")} user / user ${t("LOGIN.DEMO_ACCOUNTS_USER")}.",
                    style = MaterialTheme.typography.bodySmall,
                )
            }
        }
    }
}

@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun DoctorDayPicker(
    doctors: List<Doctor>,
    onSearch: (doctorId: Int, day: String) -> Unit,
) {
    val t = LocalTranslations.current::t

    // estado local, conservado entre rotaciones de pantalla
    var doctorId by rememberSaveable { mutableStateOf<Int?>(null) }
    // el día elegido, en formato "yyyy-MM-dd": LocalDate.toString() produce
    // exactamente este formato (ISO 8601), el que espera el servidor - ya no hace
    // falta el paquete intl de la versión Flutter
    var day by rememberSaveable { mutableStateOf(LocalDate.now().toString()) }
    var calendarOpen by remember { mutableStateOf(false) }

    // los tres elementos del componente, preparados una sola vez y luego dispuestos
    // de forma distinta según el ancho disponible (ver más abajo). Son
    // LAMBDAS @Composable: solo se MUESTRAN cuando se las llama.
    val doctorField = @Composable { modifier: Modifier ->
        DropdownList(
            label = t("DOCTOR_DAY_PICKER.DOCTOR_LABEL"),
            placeholder = t("DOCTOR_DAY_PICKER.CHOOSE_DOCTOR"),
            items = doctors,
            selectedId = doctorId,
            idOf = { it.id },
            itemLabel = { "${it.title} ${it.firstName} ${it.lastName}" },
            onSelect = { doctorId = it },
            modifier = modifier,
        )
    }
    val dayField = @Composable { modifier: Modifier ->
        OutlinedTextField(
            value = day,
            onValueChange = {},
            readOnly = true,
            singleLine = true,
            label = { Text(t("DOCTOR_DAY_PICKER.DAY_LABEL")) },
            // el ícono de calendario abre el selector de fecha
            trailingIcon = {
                IconButton(onClick = { calendarOpen = true }) {
                    Icon(Icons.Filled.DateRange, contentDescription = t("DOCTOR_DAY_PICKER.PICK_DAY"))
                }
            },
            modifier = modifier,
        )
    }
    val scheduleButton = @Composable { modifier: Modifier ->
        Button(
            // botón deshabilitado mientras no se haya elegido un médico
            enabled = doctorId != null,
            onClick = { doctorId?.let { onSearch(it, day) } },
            modifier = modifier,
        ) {
            Text(t("DOCTOR_DAY_PICKER.VIEW_SCHEDULE"))
        }
    }

    Card(modifier = Modifier.fillMaxWidth()) {
        // BoxWithConstraints: da acceso al ancho REALMENTE
        // disponible (maxWidth) - el LayoutBuilder de la versión Flutter.
        // Pantalla estrecha (teléfono en vertical): los tres elementos uno
        // debajo del otro; pantalla ancha: en una sola fila.
        BoxWithConstraints(modifier = Modifier.padding(16.dp)) {
            if (maxWidth < 600.dp) {
                Column(verticalArrangement = Arrangement.spacedBy(12.dp)) {
                    doctorField(Modifier.fillMaxWidth())
                    dayField(Modifier.fillMaxWidth())
                    scheduleButton(Modifier.fillMaxWidth())
                }
            } else {
                Row(
                    horizontalArrangement = Arrangement.spacedBy(12.dp),
                    verticalAlignment = Alignment.CenterVertically,
                ) {
                    // weight(...): reparte el ancho entre los tres
                    // elementos (5/12, 4/12, 3/12) - el flex: 5, 4, 3 del
                    // Expanded de la versión Flutter
                    doctorField(Modifier.weight(5f))
                    dayField(Modifier.weight(4f))
                    scheduleButton(Modifier.weight(3f))
                }
            }
        }
    }

    // el calendario: un diálogo mostrado mientras
    // calendarOpen sea true (el mismo principio que BookingDialog)
    if (calendarOpen) {
        // DatePicker trabaja en milisegundos desde el 1 de enero de 1970,
        // a medianoche UTC: convertimos en ambos sentidos con java.time
        val state = rememberDatePickerState(
            initialSelectedDateMillis = LocalDate.parse(day)
                .atStartOfDay(ZoneOffset.UTC).toInstant().toEpochMilli(),
        )
        DatePickerDialog(
            onDismissRequest = { calendarOpen = false },
            confirmButton = {
                TextButton(onClick = {
                    state.selectedDateMillis?.let { millis ->
                        day = Instant.ofEpochMilli(millis).atZone(ZoneOffset.UTC).toLocalDate().toString()
                    }
                    calendarOpen = false
                }) { Text(t("DOCTOR_DAY_PICKER.OK")) }
            },
            dismissButton = {
                TextButton(onClick = { calendarOpen = false }) {
                    Text(t("DOCTOR_DAY_PICKER.CANCEL"))
                }
            },
        ) {
            DatePicker(state = state)
        }
    }
}

private val TIME_COLUMN_WIDTH = 116.dp

// "8:00", "8:20"...: los minutos siempre con dos dígitos
private fun formatTime(h: Int, m: Int): String = "$h:${m.toString().padStart(2, '0')}"

@Composable
fun ScheduleView(
    schedule: DoctorDaySchedule?,
    canEdit: Boolean,
    onBook: (SlotJson) -> Unit,
    onCancel: (AppointmentJson) -> Unit,
) {
    val t = LocalTranslations.current::t

    // todavía no hay agenda: un simple mensaje de invitación
    if (schedule == null) {
        Text(
            text = t("SCHEDULE.EMPTY_STATE"),
            color = MaterialTheme.colorScheme.outline,
            modifier = Modifier.padding(vertical = 24.dp),
        )
        return // una función @Composable puede detenerse aquí: no se muestra nada más
    }

    Card(modifier = Modifier.fillMaxWidth()) {
        Column(modifier = Modifier.padding(16.dp)) {
            val doctor = schedule.doctor
            Text(
                text = "${t("SCHEDULE.TITLE_PREFIX")} ${schedule.day} - ${doctor.title} ${doctor.firstName} ${doctor.lastName}",
                style = MaterialTheme.typography.titleMedium,
            )
            // encabezados de columna: el mismo ancho de primera columna que
            // en cada fila (TIME_COLUMN_WIDTH), para que las columnas
            // queden alineadas
            Row(modifier = Modifier.fillMaxWidth().padding(top = 12.dp, bottom = 4.dp)) {
                Text(t("SCHEDULE.COLUMN_SLOT"), fontWeight = FontWeight.Bold, modifier = Modifier.width(TIME_COLUMN_WIDTH))
                Spacer(Modifier.width(8.dp)) // el espaciado entre las columnas de las filas
                Text(t("SCHEDULE.COLUMN_STATUS"), fontWeight = FontWeight.Bold)
            }
            HorizontalDivider()
            // una fila por franja. Un simple bucle forEach, en una
            // Column: aquí no se usa LazyColumn (la lista "perezosa" de Compose,
            // que solo construye las filas visibles), porque esta
            // agenda ya está colocada en una Column desplazable (ver App.kt),
            // y una docena de filas no justifican esta optimización.
            schedule.slots.forEach { daySlot ->
                SlotRow(daySlot, canEdit, onBook, onCancel)
                HorizontalDivider()
            }
        }
    }
}

@Composable
private fun SlotRow(
    daySlot: DoctorDaySlot,
    canEdit: Boolean,
    onBook: (SlotJson) -> Unit,
    onCancel: (AppointmentJson) -> Unit,
) {
    val t = LocalTranslations.current::t
    val slot = daySlot.slot
    val appointment = daySlot.appointment

    Row(
        modifier = Modifier.fillMaxWidth().padding(vertical = 6.dp),
        verticalAlignment = Alignment.CenterVertically,
        horizontalArrangement = Arrangement.spacedBy(8.dp),
    ) {
        // el horario: un ancho fijo, el mismo que el del encabezado
        Text(
            text = "${formatTime(slot.startHour, slot.startMinute)} - ${formatTime(slot.endHour, slot.endMinute)}",
            modifier = Modifier.width(TIME_COLUMN_WIDTH),
        )
        // el estado: una insignia verde "Free", o el nombre del paciente
        Surface(
            shape = RoundedCornerShape(8.dp),
            color = if (appointment == null) Color(0xFFC8E6C9) else MaterialTheme.colorScheme.secondaryContainer,
            // weight(1f): el estado ocupa todo el ancho que dejan libre
            // el horario y el botón
            modifier = Modifier.weight(1f),
        ) {
            val client = appointment?.client
            Text(
                text = if (appointment == null) t("SCHEDULE.FREE") else "${client?.title ?: ""} ${client?.firstName ?: ""} ${client?.lastName ?: ""}",
                style = MaterialTheme.typography.bodyMedium,
                modifier = Modifier.padding(horizontal = 8.dp, vertical = 4.dp),
            )
        }
        // el botón solo existe para el rol ADMIN; reserva una franja
        // libre, o cancela la cita de una franja ocupada
        if (canEdit) {
            // SIN weight(...) aquí: el botón toma el ancho de su texto.
            // Una primera versión le imponía una cuarta parte de la fila
            // (weight(0.25f)): en un teléfono en vertical, la etiqueta
            // "Réserver" (UI en francés) se truncaba entonces como "Rése" (ver capítulo 5).
            OutlinedButton(
                onClick = { if (appointment == null) onBook(slot) else onCancel(appointment) },
                // relleno interno reducido (24 dp por defecto a cada lado)
                contentPadding = PaddingValues(horizontal = 12.dp),
                // un ancho mínimo común: los botones "Book" y
                // "Cancel" tienen así el mismo ancho, y las columnas permanecen
                // alineadas de una fila a la siguiente
                modifier = Modifier.widthIn(min = 96.dp),
            ) {
                Text(if (appointment == null) t("SCHEDULE.BOOK") else t("SCHEDULE.CANCEL_APPOINTMENT"), maxLines = 1)
            }
        }
    }
}
