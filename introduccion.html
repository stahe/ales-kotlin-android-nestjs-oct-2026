    Este documento es un producto de Claude, la IA de Anthropic. Su propósito es adaptar el documento “Un ejemplo cliente/servidor - AngularJS 1.x / Spring 4” de dos maneras:

    • el cliente AngularJS 1.x se reemplaza por una aplicación Android nativa escrita en [Kotlin] con [Jetpack Compose];
    • el framework web Java Spring MVC se reemplaza por el framework web [NestJS];

    Para ello, sigue, capítulo por capítulo, el documento “Un ejemplo cliente/servidor - Flutter / NestJS (2026)”: mismo servidor, misma base de datos, misma arquitectura del cliente; solo cambia el framework del cliente, ya que Flutter (Dart) se reemplaza por Jetpack Compose (Kotlin).

    Claude, de Anthropic (IA), hizo la mayor parte del trabajo:

    • generación del código: Claude generó todo el código del cliente Kotlin. Lo compiló y lo probó él mismo en un emulador de Android en la computadora del revisor, con su autorización; las capturas de pantalla del emulador se tomaron durante estas pruebas;
    • generación del curso en formato ODT: Claude generó el documento, que el revisor leyó y probó siguiéndolo paso a paso.

    Nota 1: Si el objetivo principal del lector es “aprender NestJS”, hay una introducción a este framework web en el documento Introducción al lenguaje TypeScript y al framework web NestJS mediante ejemplos. En este documento, el servidor NestJS se trata como una caja negra. Se explica cómo usarlo, pero no se describe su código.

    Nota 2: El lenguaje de programación utilizado en este documento es [Kotlin]. Se supone que se conocen sus fundamentos (clases, clases de datos, nulabilidad, lambdas, funciones de extensión, colecciones, etc.): se tratan en el curso de Kotlin. Los conceptos propios de Android o de Jetpack Compose, así como las corrutinas, se explican a lo largo del documento.

    Nota 3: Claude se refiere con frecuencia al cliente [Flutter] del curso “Un ejemplo cliente/servidor - Flutter / NestJS” (2026), del cual este documento es una adaptación, y a veces a los clientes web Angular, React y Vue.js de la misma aplicación. Estas comparaciones ayudan a los lectores que conocen alguno de estos frameworks, pero no es necesario conocer ninguno para seguir este documento.

    Nota 4: Si considera que las explicaciones de Claude no son suficientes, envíele una solicitud pidiendo aclaraciones sobre un punto específico de su curso. Esto suele ser útil.

    ==

    Este documento es una continuación del curso “Un ejemplo cliente/servidor - AngularJS 1.x / Spring 4,” escrito en 2014. Ese documento original construía una pequeña aplicación para la gestión de citas médicas (“[RdvMedecins]”) con un servidor Spring 4 / Spring Data / Spring MVC y un cliente AngularJS 1.x.

    Doce años después, los dos frameworks utilizados han evolucionado de manera significativa, o incluso han sido reemplazados en el uso común:

    • del lado del servidor, [NestJS] se ha consolidado como uno de los frameworks Node.js/TypeScript más utilizados para construir aplicaciones web estructuradas, con una filosofía similar a la de Spring (módulos, controladores, servicios, inyección de dependencias);
    • del lado del cliente, cada vez se accede más a las aplicaciones desde un teléfono. Por ello, este documento describe una aplicación Android NATIVA: escrita en [Kotlin], el lenguaje recomendado por Google para Android desde 2019, y con una interfaz descrita mediante [Jetpack Compose], la biblioteca de interfaz de usuario declarativa de Android (estable desde 2021), que reemplaza el antiguo sistema de vistas descritas en XML.

    El objetivo de este documento es retomar el caso de estudio original (la misma aplicación, las mismas funcionalidades, la misma base de datos) y reconstruirlo con las herramientas actuales, manteniendo en la medida de lo posible la misma progresión didáctica del documento de 2014 y de su variante Flutter de 2026.

    1.1. Una reconstrucción paso a paso

    El documento original tenía aproximadamente 300 páginas y cubría, además de la funcionalidad central de la aplicación y la autenticación basada en roles (Spring Security), doce ejemplos progresivos para aprender AngularJS 1.x paso a paso. Al igual que la variante Flutter, este documento cubre:

    • la arquitectura general de la aplicación (sin cambios en lo esencial);
    • la base de datos (sin cambios, salvo por el agregado de la tabla [users]);
    • la instalación del servidor [NestJS] completo, cuyas funcionalidades de consulta y de reserva/cancelación de citas se prueban con Postman; su código no se trata aquí;
    • la autenticación basada en tokens (JWT) y el control de acceso basado en roles (ADMIN/USER) de este servidor; solo aprenderemos a usarlos, primero mediante Postman y luego mediante el cliente;
    • el cliente Android correspondiente, con las mismas funcionalidades, una pantalla de inicio de sesión, una interfaz adaptada al rol del usuario conectado (Material Design 3) y la posibilidad de cambiar la interfaz entre francés e inglés ([TranslationsService]).

    En este documento se omiten dos funcionalidades del documento original, igual que en la versión Flutter: el modo “debug” del cliente original, que se dejó fuera deliberadamente (véase el capítulo 6), y la configuración de un retardo de red artificial, que se pospuso para una etapa posterior.

    1.2. A quién va dirigido este documento

    Este documento no supone conocimientos previos de Android, de Jetpack Compose ni de [NestJS]. Cada concepto nuevo (activity, función @Composable, estado, ViewModel, corrutina, interceptor HTTP, etc.) se explica a medida que aparece. Sin embargo, algunos conocimientos básicos siguen siendo útiles:

    • un conocimiento básico del lenguaje Kotlin (véase el curso de Kotlin);
    • un conocimiento básico de los intercambios HTTP (métodos GET/POST, formato JSON);
    • experiencia en el uso de la línea de comandos (cd, npm install...).

    No se requiere conocer Flutter: las numerosas comparaciones con el cliente Flutter están pensadas para los lectores que han seguido ese curso, pero cada concepto se explica primero por sí mismo.

    1.3. La arquitectura de la aplicación

    La arquitectura general de la aplicación no ha cambiado desde el documento original:

    • el cliente presenta al usuario una única interfaz, construida sobre el modelo de Componentes (vista + lógica asociada), que se apoya en servicios para comunicarse con el servidor; en este caso, una aplicación Android que se ejecuta en el sistema del teléfono;
    • el usuario interactúa con las pantallas de la aplicación. Las acciones del usuario a veces requieren enviar una solicitud al servidor [NestJS], que la procesa y devuelve una respuesta JSON; esta respuesta se utiliza para actualizar la pantalla que se muestra al usuario.

    La aplicación estudiada tendrá la siguiente arquitectura:

    • En [1], el usuario de la aplicación Android consulta la capa [Presentation] [2] de la aplicación;
    • para ejecutar la acción solicitada por el usuario, la capa [Presentation] [2] puede consultar la capa [Services] [3];
    • Para prestar el servicio solicitado, la capa [3] puede necesitar consultar [4], el servidor JSON remoto implementado con [NestJS];
    • Según la solicitud recibida en [5], pueden consultarse las capas [6-8];
    • la respuesta del servidor recorre las capas [2-8] en orden inverso;
    • la pantalla que se muestra al usuario ([1]) refleja esta respuesta.

    Nota: Si la arquitectura del proyecto le resulta confusa, vuelva a consultar este diagrama. Tenga en cuenta que el SGBD lo gestiona el servidor, no el cliente.

    1.4. Herramientas utilizadas

    Este documento utiliza las siguientes herramientas (su instalación se detalla en los capítulos 1 y 2):

    • Node.js (versión 22 o posterior) y npm, para ejecutar el servidor [NestJS];
    • [Android Studio], el entorno de desarrollo de Google para Android. Proporciona todo lo que el cliente necesita: el editor de código (basado en IntelliJ IDEA), el Android SDK, un JDK (el JetBrains Runtime), el emulador de Android y la herramienta de compilación [Gradle]. A diferencia del curso de Flutter, donde Android Studio se usaba solo para instalar el Android SDK, aquí sirve como editor del cliente;
    • Visual Studio Code (u otro editor) para el servidor NestJS, si desea ver su código;
    • [MySQL] 8 para la base de datos, instalado con Laragon;
    • Postman (u otro cliente HTTP) para probar las URL del servidor;
    • un teléfono Android (opcional): un emulador basta para seguir todo este documento.

    1.5. Funcionalidades de la aplicación

    Las funcionalidades “de negocio” de la aplicación [RdvMedecins] son las mismas que las de las versiones anteriores:

    • un consultorio médico emplea a varios médicos, cada uno con sus propias franjas horarias de consulta;
    • un usuario debe iniciar sesión (nombre de usuario/contraseña) para acceder a la aplicación;
    • una vez iniciada la sesión, el usuario puede seleccionar un médico y un día, y ver la agenda del médico para ese día: cada franja horaria aparece como disponible o reservada;
    • un usuario con el rol ADMIN también puede reservar una franja horaria disponible para un paciente de su elección y cancelar una cita existente;
    • un usuario con el rol USER puede ver las agendas, pero no puede reservar ni cancelar citas (acceso de solo lectura).

    Arriba se muestra la aplicación en el emulador de Android: la pantalla de inicio de sesión, luego la agenda de un médico y, por último, la pantalla después de reservar una franja horaria.

    1.7. Organización de este documento

    • Capítulo 1 - Configuración del entorno de trabajo: instalar Android Studio y el SDK de Android, abrir el proyecto del cliente, crear un emulador y preparar un teléfono.
    • Capítulo 2 - Instalación del servidor [NestJS]: instalar Laragon y la base de datos MySQL, configurar, iniciar y probar el servidor, y luego ejecutar el cliente por primera vez.
    • Capítulo 3 - Introducción a Android y a Jetpack Compose: activities, funciones @Composable, estado y recomposición, CompositionLocal, corrutinas, ciclo de vida y ViewModel, con el equivalente en Flutter de cada uno.
    • Capítulo 4 - El cliente Kotlin de la aplicación [RdvMedecins]: la arquitectura del cliente, cada uno de sus archivos y un recorrido paso a paso por la aplicación completa.
    • Capítulo 5 - Ejecución de la aplicación: emulador, teléfono, APK, y lo que debe saber sobre la red, el tráfico HTTP sin cifrar, la rotación de la pantalla y las pantallas estrechas; por último, lo que haría falta para dirigirse también a iOS, el escritorio y la web.
    • Capítulo 6 - Conclusión y próximos pasos.
